How This Workflow Works OAuth → Setup (state model) → Session → Extraction + DB at every step
Full roundtrip: authenticate via OAuth refresh token → seed project folders → upload PDFs with the 5-step QC Review state model injected via pdf-lib (on by default, no Bluebeam API needed) → create Session → review in Revu → downstream extraction writes markup snapshots to SQLite. Tab 2 reads entirely from the DB snapshot — not from the Bluebeam API on every load.

Auth + Setup

  • POST /poc/auth/refresh rotates the access token via Bluebeam OAuth. Required before any BB API call.
  • setup-project verifies folders. upload-to-project injects 5-step QC Review state model (removes stale models first, then adds clean model), then uploads to review-documents.
  • DB writes: projects (configure upsert), files (upload).

Session

  • create-session → register-webhook → checkout-to-session → invite-reviewers.
  • Session written to DB sessions table with polling schedule.
  • DB writes: sessions (create), files updated with sessionFileId (checkout).

Extraction + DB

  • downstream-process: checkin → exportmarkups job → XML parse → snapshot saved to DB.
  • Poller auto-runs on schedule writing fresh snapshots.
  • DB reads: Tab 2 reads from snapshots table. Pull Snapshot button re-queries DB.
